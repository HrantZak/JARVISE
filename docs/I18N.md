# Language

JARVIS is a Russian-first assistant. Russian and English are both primary
languages; **Russian is the default**, and neither is a translation layer bolted
onto the other.

## How it is wired

| Piece | Where | What it does |
|---|---|---|
| `Language` | `src/i18n` | The language enum, ISO codes, endonyms, Qt locale names, and a tolerant parser |
| `LanguagePolicy` | `src/i18n` | Turns the chosen language into the language section of the LLM system prompt |
| `TranslationManager` | `src/app` | Loads `.qm` catalogues, swaps them at run time, retranslates QML |
| `general.language` | `config.json` | The persisted choice, `"ru"` or `"en"` |
| `i18n/jarvis_*.ts` | repo root | The catalogues, 238 strings each |

`src/i18n` is Qt-free on purpose: the llama.cpp backend that will consume
`LanguagePolicy` in Phase 3 has no business linking QtCore to build a prompt
string.

## Switching at run time

Selecting a language in **SETTINGS → LANGUAGE** applies immediately - no
restart, and the current page and scroll position survive. Under the hood:

1. `TranslationManager::apply()` loads the new catalogue **before** removing the
   old one, so a missing catalogue leaves the interface in the language it was
   already speaking rather than half-translated.
2. `QLocale::setDefault()` follows the language, which is what makes the HUD
   clock read `ПН 10 АВГ. 2026` instead of `MON 10 AUG 2026`.
3. `QQmlApplicationEngine::retranslate()` re-evaluates every `qsTr()` binding.
4. `languageChanged()` tells the C++ objects that cached `tr()` results -
   `AiCoreModel` and `SystemMonitor` - to rebuild theirs.

## What is never translated

Per the project rules, the presentation layer is the only thing that changes
language. These stay exactly as written, in every language:

- **Internal names**: `AiCoreModel`, `SystemMonitor`, `ILLMBackend`, `ToolEngine`
- **State keys**: `OFFLINE`, `LISTENING`, `THINKING`… The Core exposes
  `stateKey` (never translated, used by the QML state machine and the theme
  palette) alongside `stateLabel` (translated, shown to the user). Navigation
  does the same with `key` and `name`.
- **Proper nouns**: JARVIS, Visual Studio, Steam, llama.cpp, whisper.cpp, GGUF,
  Vulkan, `config.json`
- **Technical abbreviations**: CPU, GPU, RAM, VRAM, SSD
- **Paths, file names and commands**

The system prompt states this rule explicitly, because models otherwise
translate "Visual Studio" into "Визуальная студия" and the application launcher
stops matching anything.

## Updating the catalogues

After adding or changing any user-visible string:

```bash
cmake --build build/msvc-debug --target update_translations
python scripts/fill_translations.py
```

`fill_translations.py` **fails** if any string lacks a Russian translation, so a
newly added `qsTr()` cannot silently ship as English in the Russian interface.
Add the missing entry to the `RUSSIAN` map in that script.

`BY_CONTEXT` in the same script handles strings whose meaning depends on where
they appear: `MEMORY` is `ПАМЯТЬ` in the navigation rail and on the memory page,
but `ОЗУ` when it labels a RAM gauge.

### Two traps worth knowing

**lupdate only sees string literals.** A `const char*` variable passed to
`QCoreApplication::translate()` is invisible to it. Wrap the literal in
`QT_TRANSLATE_NOOP` at the call site - see `SystemMonitor.cpp`.

**lupdate does not expand user-defined macros.** Hiding a `QT_TRANSLATE_NOOP`
inside your own macro silently drops the string from the catalogue. Both of
these cost a debugging round trip during Phase 2's language work.

## Typography

`tests/tst_i18n.cpp` asserts that Bahnschrift, Cascadia Mono and Segoe UI each
declare Cyrillic support and carry a glyph for every letter of the Russian
alphabet, including **Ё** and **ё**, plus `№ — « » ·`. If a future font change
breaks Cyrillic coverage, the build fails rather than the user's eye catching a
substituted glyph mid-word.

Bahnschrift has no `▼ ▲` triangles. That is asserted too, which is why the HUD
sets its throughput arrows in Cascadia Mono and never in the display face.

## Layout under longer text

Russian runs longer than English - `АВТОМАТИЗАЦИЯ` against `AUTOMATION`,
`СИСТЕМНЫЕ ИНСТРУМЕНТЫ` against `SYSTEM TOOLS`. Two theme tokens absorb it:

- `Theme.navWidth` (214) fits the longest navigation label in any language
- `Theme.labelColumnWidth` (214) fits the longest `InfoRow` label

The AI Core steps its display size down for state names longer than nine
characters, so `ОБРАБАТЫВАЮ` sits inside the ring exactly as `THINKING` does.

## UTF-8

The whole project compiles with `/utf-8`, so source and execution charset are
both UTF-8 and no escaping is needed anywhere. `tst_i18n` covers:

- Cyrillic values surviving a `config.json` write-and-read round trip
- the config store working under a Cyrillic path such as
  `…\Пользователь Ёлка\ЯДРО` (real users have Cyrillic account names)
- `ёлка`.toUpper() producing `ЁЛКА`
- literals in C++ sources keeping their bytes through the toolchain

## Adding a language

1. Add the enum value and its row in `kEntries` (`src/i18n/src/Language.cpp`).
2. Add `i18n/jarvis_<code>.ts` to `TS_FILES` in the root `CMakeLists.txt`.
3. Run the two commands above and fill in the translations.
4. Add the reply-language name to `LanguagePolicy::replyLanguageName()`.

Nothing else changes: the picker, the config schema and the switching logic are
all driven by `kSupportedLanguages`.
